## 標準フロー

### 1. 受付

変更依頼には次を含める。

- 対象ページ
- 現在の表示
- 変更後の表示
- 根拠となる正本
- 希望公開日
- プレビューのみか、本番公開までか

### 2. 作業

- 最新の`main`から作業ブランチを作る
- 変更範囲を限定する
- 日本語と多言語生成元を同時に更新する
- 無関係な整形や全面書き換えを混ぜない

### 3. 確認

Pull Requestに次を記録する。

- 変更理由
- 変更ファイル
- 変更前後
- 事実の根拠
- PC・スマートフォン確認
- 多言語確認
- 構造化データとリンク確認
- 公開後に確認する項目

### 4. 承認・公開

- 杉本さんの承認後に`main`へ反映する
- Cloudflareのデプロイ成功を確認する
- https://buttokuikiro.com/ を実際に開いて確認する
- 重要変更では該当ページと構造化データの双方を確認する

## ロールバック

不具合時は履歴を書き換えず、問題のコミットを`revert`する。直前の正常コミットを特定し、Cloudflareへ再公開した後、公開サイトを確認する。

## 管理境界

このリポジトリが管理するのは「麺屋 ぶっとく生きろ。公式サイト」のみ。GAS台帳、売上転記、勤怠、年間損益、他店舗サイトは別の正本で管理し、同じリポジトリへ混在させない。

## 次の整備

1. CloudflareとGitHubの接続状態を確認
2. `main`の直接更新を防ぐ保護ルールを設定
3. HTML・リンク・構造化データの自動検査を追加
4. リポジトリの公開範囲を、Cloudflare連携を壊さない条件で再判断
5. 小さな変更で「依頼→PR→承認→公開→確認」を一度通して運用受入
